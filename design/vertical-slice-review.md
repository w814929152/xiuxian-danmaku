## 1. MDA 分析

### 1.1 Mechanics（机制层）—— 扎实，且互相咬合

实际读到的机制（非文档转述，均以代码为准）：

| 机制 | 实现位置 | 数值 |
| --- | --- | --- |
| 四色免疫 | `Player.take_hit()` L333 | 弹色 == 袍色 → 穿过且不重置"十息回气" |
| 同源共振 | `Enemy.hit()` L164 / `Elite.hit()` L196 | 小妖/妖将吃同色飞剑 **+50%**；**Boss 不吃**（`Boss.hit()` 无共振项） |
| 实时换袍 | `Player.do_swap()` | CD 0.20s，换袍瞬间给 0.18s 无敌帧 |
| 属性法罩 | `Boss._ward()` | 仅困难；开启 5.2s / 关闭 3.2~4.8s；色从玩家两件道袍抽 |
| 异色衰减 | `Boss.hit()` L302 | 困难 0.60（简单/普通无法罩，恒 1.0） |
| 属性法罡 | `Elite.hit()` L196-205 | 异色 35%；**法罡不破本体不掉血**；破罡虚弱 4.5s；2 层用完永久破防 |
| 符光过热 | `Player._update_heat()` | +20/s，满 100 闭锁，停火 0.5s 后 −30/s，散到 60 解锁；吃黄弹 −30 |
| 狂暴 | `Boss._check_enrage()` | 跌破 30% 触发；四色螺旋 0.09s/轮 × 4 弹 |
| 道具 | `Pickup` / `Level` | 斩妖 18% + 每波固定 1 = 每局 6~7 个；权重 [30,24,26,20] |

**机制层评价：8.5/10。** 每一条规则都落在"四色"这一个轴心上，没有游离机制。特别值得肯定的三处：

- **免疫色 = 增伤色**：穿红袍既免疫红弹又对红妖 +50%，攻守激励完全对齐，玩家不需要做"我要攻还是要守"的内耗决策 —— 这是干净的设计。
- **法罡/法罩色只从玩家道袍抽**（`Elite.setup()` L83、`Boss._ward()` L149）：把"破罡死局"从机制上根除。这不是偷懒，是可行性优先级的正确排序。
- **吃黄弹散热**：戊土袍玩家被黄弹打中反而是好事（−30 过热）。反直觉的正反馈，是整个设计里最聪明的一笔。

### 1.2 Dynamics（涌现层）—— 有真东西，但只在两处爆发

玩家实际会涌现出的行为链：

```
读色（看到红妖/红弹逼近）
  → 换红袍（0.2s CD）
  → 双收益：免疫红弹 + 对红妖 +50%
  → 红妖秒杀 → 换下一色
```
这条闭环成立且爽。**但它的触发条件在 run 的大部分时间里不成立**（见 §2）。

另外两条涌现：
- **过热应急**：黄袍过热闭锁 → 换袍立刻恢复输出（非黄袍分支不检查 `overheated`）。黄袍玩家可以主动"吃黄弹散热"来压缩停机。这是高手向的节奏操作，且**没有任何文案提示它存在** —— 隐藏技巧，只靠悟。
- **破罡窗口博弈**：妖将破罡后 4.5s 内本体任意色全额，玩家要在"窗口里多吃两发弹换输出"和"稳一手"之间取舍。真博弈。

**涌现层评价：7/10。** 质量高，但覆盖面窄。

### 1.3 Aesthetics（美感层）—— 感官与幻想满分，竞争与表达接近零

| MDA 八美感 | 表现 | 评价 |
| --- | --- | --- |
| Challenge 挑战 | 妖潮段低、妖将中、Boss 高 | 分布失衡 |
| Fantasy 幻想 | 赤炎/玄冰/太清/戊土、道袍/法相/法罡/元神、道成/道消 | ✅ 强 |
| Sensation 感官 | 像素 sprite + 四色发光 + 狂暴血光三层节奏 + 粒子 | ✅ 强 |
| Submission 消遣 | 单局 60~70s，操作负担轻 | ✅ 合适 |
| Discovery 发现 | 每局结构完全固定，唯一变量是道袍组合 + 道具随机 | ❌ 弱 |
| Expression 表达 | 6 种道袍组合，但结算不展示 build | ❌ 弱 |
| Competition 竞争 | 无排行榜、无最高分、无分享 | ❌ **零** |
| Fellowship 社群 | 单人、无社交 | N/A（arcade 可接受） |

**"修仙弹幕射击"这个核心幻想兑现了吗？**
- **"修仙"**：✅ 完全兑现。词汇表自洽，四色对应五行，道袍库 LORE 写得很认真。
- **"弹幕"**：⚠️ **只在 Boss 战兑现**。妖潮段屏幕常驻弹数估算只有 4~8 发（见 §2.2），远未构成"弹幕"。

### 2.1 曲线图（普通档，估算）

   │            ▂▇█▂

   │   ▁▂▁                                   
低 │▁▁▁                                      
   └────────────────────────────────────────► 时间(s)
    0    10   20   30   40   50   60   70
    │    │    │    │    │    │    │
    intro W1  空  W2+将 空  W3+将 空  老祖

普通档单局时长明细（按代码时序累加）：

| --- | --- | --- |

| 第 1 重妖潮（5×0.62 生成 + 清场） | ~4.6 | 低挑战 |
| 横幅 1.8 + `wait(1.3)` | 3.1 | **空档** |

| 血魔老祖（约 19.4 + 演出 1.92 + wait 1.3） | ~22.6 | 高 → 峰值3 |
| **合计** | **≈ 63~67s** | 空档占比 **≈ 23%** |

### 2.2 🔴 无聊点 A：妖潮段挑战密度严重不足

**证据链（全部来自代码，非估计）：**

- 玩家射速：`FIRE_CD = 0.105` → **9.52 齐射/秒**
- 赤炎剑袍单齐射：`rows()=2`，`sword_damage()=8` → 16 伤/齐射 → **理论 152.4 DPS**
- 小妖血量（`Enemy.setup()`）：红 26 / 蓝 34 / 黄 30 / 白 42（普通档 ×1.0）
- 同源共振同色 +50%

→ **单只小妖 TTK = 0.21 ~ 0.53 秒**

- 生成间隔：`await wait(0.62)` → 每 0.62s 出一只
- 小妖出手间隔：`fire_cd *= 2.0 - bullet_scale()` = 1.25~1.9 × 1.2 = **1.5~2.28s**，且首次开火延迟 `_fire = 0.7~1.5s`

→ **结论：小妖从入场到死，平均只来得及开 0~1 轮火。** 三波 20 只小妖，屏幕常驻敌机 1~2 只，常驻弹幕 4~8 发。

这不是"弹幕游戏"，这是"打靶游戏"。**妖潮段占了单局约 45% 的墙钟时间，却是整局密度最低的部分。**

### 2.3 🔴 无聊点 B：三处节奏断崖

`_run()` 里横幅 + `wait()` 合计 **15.3 秒纯空档，占单局 23%**。其中开场一段就有 4.6s，玩家按下"开始"后要干等 4.6 秒才见到第一个敌人。

每一次峰值（妖将）后面紧跟一次断崖，心流刚建立就被打断 —— 这是典型的"锯齿型"节奏，玩家记住的是"被打断"而不是"爽"。

### 2.4 🟡 挫败点 A：简单档的两个高潮被压成闪电

- 简单档 Boss `boss_hp() = 1000`，玩家有效 DPS ≈ 129（152 × 85% 命中率）→ **Boss 战仅约 7.8 秒**，两重法相在 7.8 秒内切完，形态变化根本读不到。
- 狂暴段（30%→0%）= 300 HP → **仅 2.3 秒**。"三档共有"的招牌机制，在简单档是"红光一闪就没了"。

| 档位 | Boss 战时长 | 狂暴段时长 |
| --- | --- | --- |
| 简单 | ~7.8s | **~2.3s** |
| 普通 | ~19.4s | ~5.8s |
| 困难 | ~34.9s | ~10.5s |

### 2.5 🟡 挫败点 B：元神只进不出，且没有"你已经没救了"的反馈

`波次结束不再回血 —— 元神只靠回春丹`。回春丹权重 30/100，每局约 6~7 个道具 → **期望 1.8 个回春丹 = 最多回 40 点**。

玩家 100 血、每发弹 10 伤、受击无敌 0.85s → 全局容错 **10 次受击（白袍 11 次）**。

若玩家在妖潮段掉到 30 血，Boss 战实质已死，但：
- HUD 不提示"危险"（只有血条颜色在 <30% 时变深红）
- 玩家会打到 Boss 战才死，浪费 20~35 秒
- 有 `R` 重来本关（`HUD._unhandled_input`），但玩家不知道自己该不该用

→ 死亡螺旋 + 无反馈，是 arcade 类型最忌讳的挫败形态。

### 2.6 🟢 值得表扬：难度阶梯的"感知差异"设计

`boss_phases()`：简单 2 重 / 其余 3 重；`boss_ward()`：仅困难。这让三档不是"数值 ×1.5"的偷懒缩放，而是**机制的分层解锁**。这是对的。

## 3. 玩家动机评估（SDT：自主 / 胜任 / 关联）

### 3.1 自主（Autonomy）—— ✅ 强，且是本项目最大的设计资产

- **四选二** = C(4,2) = **6 种组合**，每组合的玩法身份明确：

| 组合 | 玩法身份 |
| --- | --- |
| 赤炎 + 玄冰 | 高 DPS + 高机动（进攻型） |
| 赤炎 + 太清 | 高 DPS + 容错（稳攻型） |
| 玄冰 + 太清 | 高机动 + 容错（苟活型） |
| 戊土 + 赤炎 | 扫场 + 爆发（清怪型） |
| 戊土 + 玄冰 | 扫场 + 游走（风筝型） |
| 戊土 + 太清 | 扫场 + 容错（慢磨型） |

- **关卡内实时换袍**（0.2s CD）把自主性从"开局一次"延伸到"每秒一次"。这是本项目区别于一般弹幕射击的核心差异点，也是最大的卖点。
- 敌色均匀随机（`randi() % 4`），四色对称，**不存在天然强势色** → 6 种组合都成立，没有废组合。

**⚠️ 一处轻度主导策略风险（红线扫描）**：
赤炎剑袍 152.4 DPS vs 其余 95.2 DPS = **+60%**。而 Boss 战时长缩短 38% = **总受击机会减少 38%** —— 也就是说赤炎不只加攻，还间接加防。玄冰的 +50% 移速、太清的 10 点罡气都换不来同等的综合收益。
**建议**：不必削弱赤炎（它是"进攻型"的身份锚），但可以把玄冰/太清的非伤害收益加厚一档（如玄冰残影期短暂无敌、太清罡气上限提到 12~15），让三者的"综合收益率"拉近。

**⚠️ 另一处：戊土 + 剑影符的隐性主导**
`_update_heat()` 只认"是否在出光"，**加排不加发热**。`Beam` 每 0.2s 对光柱上**所有** `Damageable` 结算 → 戊土 + 剑影符 ×3 = 4 道贯穿全屏的 AoE，DPS 从 87.8 直接跳到约 **350（4 道 × 87.8）**，且发热不变。这是全局最强 build，且是"随机吃到 3 张剑影符"才触发 —— 强度上限受随机性支配，不可控。
**建议**：给多道符光加一个发热系数（如每多一道 +15%），或把剑影符对戊土改为"加宽光柱"而非"加道数"。

### 3.2 胜任（Competence）—— ❌ 三处缺口

**缺口 1：难度不影响分数（致命）**

穷举全部加分路径：

| 来源 | 次数 | 分值 | 小计 |
| --- | --- | --- | --- |
| 小妖 | 5+7+8 = 20 | 100 | 2000 |
| 护法妖将 | 2 | 800 | 1600 |
| 法相转换 | 普通/困难 2 次（简单 1 次） | 600 | 1200（简单 600） |
| 斩老祖 | 1 | 5000 | 5000 |
| **理论满分** | | | **普通/困难 9800 · 简单 9200** |

品阶阈值（`ResultScreen._rank()`）：6500 玄品 / **10000 地品** / **14000 天品**

→ **地品（10000）与天品（14000）在任何难度、任何表现下都不可达。满分 9800 只能落在「玄品 · 筑基」。**
→ **三档难度的分数天花板几乎相同（9800 / 9800 / 9200），挑战困难档在"灵石"上零回报。**

这是一条**硬阻塞**：一个分数驱动的 arcade 游戏，奖励阶梯的顶两级是死的，且难度阶梯没有分数回声。玩家打完一局拿到"玄品·筑基"，既不知道自己离满分多近，也没有"再打一局就能上一个品阶"的抓手。

**缺口 2：核心机制（换袍）在 2/3 的档位里不被强制教学**

- 简单 / 普通：`boss_ward() = false` → **Boss 战全程不展法罩**，换袍在 Boss 战的唯一作用变成"免疫弹色"（仍有意义，但弱）。
- 妖将：`WARD_RESIST = 0.35` 且**破罡后 4.5s 内本体任意色全额** → 不换袍只是慢 3 倍，**永远不会卡死**。

→ 一个简单档玩家可以在"几乎不主动换袍"的情况下通关。核心动词没被教会，也没被证明必要。

**换袍收益实测（第 2 重妖将：本体 552 / 单层罡 172）**：

| 打法 | 破一层罡 | 打本体 | 合计 TTK |
| --- | --- | --- | --- |
| 不换袍（异色 35%） | 172/(152×0.35) = **3.23s** | 552/152 = 3.63s | **≈ 10.1s** |
| 换袍同色（150%） | 172/(152×1.5) = **0.75s** | 552/228 = 2.42s | **≈ 3.2s** |

**换袍收益 ≈ 3.2×** —— 数值上非常成立。问题在于：**游戏从不告诉玩家这 3.2× 的存在**（横幅只说"换上同色道袍方可速破"，没有量化对比，也没有失败反馈）。

**副产品**：4.5s 虚弱窗口 + 552 血本体 → 只要破一层罡就能在窗口内打完（2.42s < 4.5s），**第 2 层法罡（重铸）在最优打法下永远用不上**。第 3 重（624 血）也只需 2.74s，同样用不上。→ 重铸机制在 90% 情况下是死内容。

**缺口 3：零持久化 = 零长期胜任信号**

全项目 grep 无 `FileAccess` / `ConfigFile` / `user://`。`Game.result_time` 声明了但**从未被赋值**（死变量）。
玩家关掉 exe，这一局的 9800 分就消失了。**跨会话的胜任感完全不存在。**

### 3.3 关联（Relatedness）—— ⚠️ 风味够，"人"与"他人"缺

**做得到位的（✅ 关联于世界观）：**
- 四色命名：赤炎 / 玄冰 / 太清 / 戊土，对应五行，不是"红蓝白黄"
- 道袍命名 + 四段 LORE（`Game.ROBE_LORE`），写得很用心
- 敌人：炎魔 / 冰妖 / 清灵 / 戊土妖；精英：护法妖将；Boss：血魔老祖 · 第 N 重法相
- 结算：道成 / 道消；元神 / 灵石 / 品阶（天品·元婴 > 地品·金丹 > 玄品·筑基 > 黄品·炼气）
- 暂停界面叫「入 定」

词汇表的一致性非常好，**没有一处术语串味**。这在 Lean 强度下属于超额完成。

**缺位的（❌ 关联于"人"与"他人"）：**
- 无角色：玩家是无名修士，老祖是无动机 Boss，妖将是无台词精英。**没有任何一句话解释"为什么要打"**。
- 无叙事推进：三档难度、6 种道袍组合、胜/败，结算文案都是固定的两行。
- 无他人：无排行榜、无最高分、无分享、无 Ghost。

**低成本补强建议**（都不需要新系统）：
1. 老祖登场 / 狂暴 / 伏诛各给一句偈语（3 行字）
2. 结算按"是否通关 × 难度 × 品阶"给不同的结语（现有 2 行 → 8 行分支）
3. 道袍库里点出师门/传承设定，把 4 件道袍串成一条线（LORE 已具备素材，只差一句"同出某某门下"）

## 4. 核心循环闭环与"再来一局"钩子

### 4.1 当前闭环

```
开始界面 → 择难度 → 择道袍(四选二) → 妖潮×3(+妖将×2) → 老祖 → 结算
                                                              │
                              ┌─────────────────────────────┤
                              │ R/J「再来一次」              │ Enter「回到标题」
                              ▼                              ▼
                    直接重开 Level（同难度同道袍）      开始界面（重走 4 步）
```

### 4.2 钩子评估：❌ **当前几乎没有钩子**

| 钩子类 | 是否存在 | 说明 |
| --- | --- | --- |
| 分数最大化 | ❌ | 分数是**固定和**，满分 9800 一局就能算出来，第二局没有提升空间 |
| 品阶爬升 | ❌ | 顶两级不可达，实际只有"玄品/黄品"两档 |
| 最高分刷新 | ❌ | 无持久化 |
| 难度挑战 | ❌ | 困难档不加分 |
| Build 试验 | ⚠️ | 6 种道袍组合有探索价值，但**换 build 需要退回标题重走 4 步**，摩擦最大 |
| 解锁/收集 | ❌ | 无 |
| 熟练度表达 | ❌ | 无计时、无连击、无无伤奖励 |
| 叙事好奇 | ❌ | 无 |

**唯一的正向钩子**：`R/J 再来一次` 一键重开、跳过所有前置界面 —— 重试摩擦极低，这个**做对了**（arcade 的黄金法则）。

**但它同时带来一个副作用**：重试直接进 Level，**跳过了择袍界面**。`Game.picked_robes` 保持不变 → 玩家想换 build 必须主动退回标题，走 4 步。**核心自主性被埋在了摩擦最大的路径后面。**

### 4.3 单局时长与节奏：✅ 基本合理

60~70 秒（普通）对 arcade 单局是**教科书级的正确长度**（参考：《Downwell》~90s、《Vampire Survivors》单局更长但自动化、《Touhou》单关 ~2min）。
问题不在总长，而在**内部 23% 是空档**（§2.3）。

## 5. 设计红线扫描

| 红线 | 状态 | 位置 / 说明 |
| --- | --- | --- |
| **主导策略** | 🟡 轻度 | ① 赤炎 +60% DPS 间接加防（§3.1）；② 戊土 + 剑影符 ×3 = 4 道全屏 AoE 且不加发热，是全局最强 build（§3.1） |
| **经济失衡** | 🔴 | 计分天花板不可达（§3.2 缺口 1）；回春丹在满血时拾取直接浪费（`apply_pickup` 返回"元神已满"） |
| **认知过载** | 🟡 | 困难档狂暴峰值：HUD 需同时承载 Boss 血条 + 法罩色 + 元神 + 罡气 + 过热 + 增益行 + 双道袍槽 + 血光边缘 + 200+ 弹幕（§5.1） |
| **支柱漂移** | 🔴 | 核心动词「换袍/读色」在妖潮段（45% 时长）和简单/普通 Boss 战（无法罩）中都是"可选优化"而非"必需操作"（§3.2 缺口 2） |

### 5.1 认知过载的两个具体点位

1. **法罩提示是整句中文**：`"法罩 · 赤炎  →  换上【赤炎剑袍】破之"`（`HUD._draw()` L278）。玩家在密集弹幕中要读完 15 个字才能做出决策。**建议改成图形化色徽记对比**（左：法罩色圆点 / 右：当前袍色圆点，不一致时闪烁），把"读句子"降为"看颜色"。

2. **一处无效信息占注意力**：`DrawUtil.txt(..., "（仅太清罡气状态下生效）", ..., 13)`（L199）—— 13px 小字，在战斗里根本读不到，但常驻在视野内。要么放大上移到教学横幅，要么删掉。

### 5.2 跨系统一致性问题（供程基岩参考，非阻塞）

| # | 问题 | 位置 |
| --- | --- | --- |
| C1 | 精英的异色惩罚 **35%** 比困难 Boss 的 **60%** 还狠，且**不随难度变化** —— 简单档玩家打妖将反而被罚得更重 | `Elite.WARD_RESIST` vs `Game.off_color_mul()` |
| C2 | 文案"三档只在老祖身上分高下 —— 妖潮一视同仁"与实现不符：小妖出手间隔确实按 `bullet_scale` 放慢（`fire_cd *= 2.0 - k`） | `DifficultySelect._draw()` L141 / `Enemy.setup()` L59 |
| C3 | `Game.result_time` 声明后从未赋值（死变量） | `Game.gd` L113 |
| C4 | 妖将 HP / 法罡按波次缩放（1.15 / 1.3）但**不按难度缩放** —— 与 C2 文案一致，但与"三档分高下"的玩家预期相反 | `Level._wave()` L78/87 |

### 5.3 可访问性红线（建议列入 Phase 7 检查表）

`Danmaku.gd` 注释明确写了：**"颜色是唯一区分维度"**（四色共用同一张白模弹丸，靠 `modulate` 染色）。
→ 对红绿色觉障碍玩家（男性约 8%），**红/黄 与 蓝/白 可能无法区分**，而这是本作的核心读写轴心。
→ **建议**：加一个可选的"符文模式"—— 在弹丸中心叠加一个高对比度的单色符号（◆ / ● / ▲ / ■），形状承载颜色信息。改动局限于 `Danmaku.setup()` 的 `_art` 与 `COLOR_GLYPH` 常量表，`Beam` / 免疫判定逻辑零改动。

## 6. 设计侧判定

# ⚠️ CONCERNS —— 不建议直接进 Phase 7

**理由：**
核心循环**是好玩的** —— 机制层咬合紧密，换袍的 3.2× 收益真实存在，妖将和老祖两场遭遇的质量足够撑住"再来一局"的冲动。**没有 FAIL，不需要推翻任何设计。**

但闭环在最后一环断了：玩家打完一局拿到"玄品 · 筑基 · 9800 分"，**不知道自己离天花板多近（9800 就是天花板）、不知道困难档有什么好处（没有）、下次打开游戏时什么都不记得（无持久化）**。这三条同时成立时，"再来一局"只能靠本能冲动，撑不住第二次、第三次。

**修复成本极低**：P0 两条加起来约半天的改动量（改阈值 + 一个 `user://` 存档文件），且**不触碰任何战斗逻辑**。这也是我判定 CONCERNS 而非 FAIL 的原因 —— 核心循环本身不需要返工，缺的是"让它被记住"的那一层。

## 7. 改进建议（按优先级排序）

### P0 —— Phase 7 前必须解决（阻塞发布）

**P0-1 修好计分天花板 + 给难度加回声**

满分 9800 / 地品 10000 / 天品 14000 → 顶两级不可达，三档分数几乎无差别。

三个方案，**请主理人转达用户拍板**：

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A（推荐）** | 阈值下调 + 难度系数：简单 ×1.0 / 普通 ×1.15 / 困难 ×1.35；阈值改为 6000 / 9000 / 12500（对基准分） | 改动量最小（约 10 行）；天品在困难档可达（9800×1.35 = 13230 ✅）；三档拉开差距 | 分数仍是"固定和"，上限可见 |
| **B** | 重做计分：基准分 ×（1 + 残余元神/100 × 0.3）× 时长系数 × 难度系数 | 分数变成"表现的镜子"，天然支持刷分；顺带奖励"无伤速通" | 需要新指标（计时、连击），改动量大；需重新标定 |
| **C** | 只调阈值：14000→9500 / 10000→7800 / 6500→5800 | 一行改动，立刻修好可达性 | 不解决"难度无回报" |

**P0-2 加本地最高分持久化**

`user://` 存一个 JSON（三档各一个最高分 + 对应道袍组合 + 品阶）。结算界面加"**新 高**"标记 + 历史最高分对照行。
→ 这是**投入产出比最高的一条**：一个文件 + 十几行代码，直接把"再来一局"的钩子从 0 变成 1。

### P1 —— 建议进 Phase 7 前解决（不阻塞，但影响口碑）

**P1-1 把"再来一局"分流成两个入口**
结算界面现在是 `R/J 再来一次`（同道袍重开）+ `Enter 回到标题`（重走 4 步）。
建议加第三个键（如 `T`）：**「换 袍 再 来」→ 直接回择袍界面（保留难度）**。
→ 把"试新 build"的摩擦从 4 步降到 1 步，直接放大本项目最强的资产（自主性）。

**P1-2 压缩三处节奏断崖**
开场 4.6s → 建议 2.0s（首波直接开始，横幅与首只小妖并行出场）。三段空档合计 15.3s → 目标 ≤ 8s。
→ 单局时长不变，但把省下的 7 秒还给战斗。

**P1-3 让妖潮段配得上"弹幕"二字**

三个方向（可单选可组合）：

| 方案 | 做法 | 说明 |
| --- | --- | --- |
| **A（推荐）** | 妖潮改成「同色潮」：每一重只出 1~2 种颜色的敌人（如第 1 重纯赤炎+玄冰） | **不加性能压力就强化支柱**：玩家必须在"免疫色覆盖"和"共振增伤覆盖"之间做取舍，换袍从可选变必需。同时解决 §5 的支柱漂移 |
| **B** | 提密度：小妖 HP ×1.8、生成间隔 0.62 → 0.42、每波数量 5/7/8 → 8/10/12 | 直接把常驻弹幕从 4~8 提到 15~25。需同步看性能余量（工程报告称绘制指令 ~105/帧，余量充足） |
| **C** | 缩短 TTK 差：降低玩家基础射速或提高小妖 HP，让单只小妖 TTK 从 0.21~0.53s 拉到 0.6~1.2s | 敌机存活更久 → 开火轮次更多 → 弹幕自然变密，不动数量 |

**P1-4 让教学说清"换袍值 3.2 倍"**
妖将横幅现在是"身披【X】法罡 —— 换上同色道袍方可速破"。
建议：破罡瞬间，若玩家用的是异色，飘一行 `"异色破罡 · 慢 3 倍"`；同色破罡时飘 `"同色破罡 · 快 3 倍"`。
→ 用一次对比把 3.2× 讲清楚，比任何横幅都有效。

### P2 —— 打磨项（可进 Phase 7 后迭代）

- **P2-1** 玄冰 / 太清的非伤害收益加厚一档，拉近与赤炎的综合收益率（§3.1）
- **P2-2** 戊土多道符光加发热系数（每多一道 +15%），或剑影符改"加宽"而非"加道"（§3.1）
- **P2-3** 妖将第 2 层法罡：把 `BROKEN_TIME` 从 4.5s 降到 3.0s，或本体 HP 提到 900+，让"重铸"真正被看到（§3.2）
- **P2-4** 满血拾取回春丹时改为不掉回春丹（重掷类型）或折算成 +200 灵石，消除浪费感
- **P2-5** 法罩提示图形化（§5.1-1）；删掉或上移 13px 的"仅太清罡气状态下生效"小字（§5.1-2）
- **P2-6** 老祖登场/狂暴/伏诛各一句偈语；结算按难度×品阶分支结语（§3.3）
- **P2-7** 简单档：`boss_hp()` 1000 → 建议 1400，狂暴段 2.3s → 3.3s（§2.4）
- **P2-8** 可访问性：加"符文模式"开关（§5.3）
- **P2-9** 结算展示本局 build（两件道袍 + 最终增益层数），补上"表达"这一美感缺口
