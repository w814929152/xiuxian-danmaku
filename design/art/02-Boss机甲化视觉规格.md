# 02 · Boss 矢量绘制规格（玩家同语汇 · v2 简化版）

> **v1（原名「Boss 机甲化视觉规格」）已于 2026-10-02 全量作废**，本文件是它的替代品。
> 冲突处以本文件为准；本文件未提及的部分一律沿用
> `design/art/01-五关视觉差异化规格.md`。
>
> **本文件描述的是已落地代码**（`scripts/art/BossArt.gd` + `scripts/entities/Boss.gd::_draw()`），
> 不是提案。改代码前先看本文件，改代码后回写本文件。
>
> 重做起因：v1 把 Boss 往「机甲」方向堆细节（铆钉 / 传感器阵列 / 散热鳍 / 倒角 / 闸齿 /
> 装甲带 / 转轴环 / 夹爪 / 观察缝），与玩家战机的简洁矢量语汇**不同源**，视觉上两套物种。

## 1 · 绘画语汇（**玩家同语汇，只有四条**）

> 基准 = `scripts/entities/Player.gd::_draw()` 与 `scripts/ui/ArmorArt.gd`。
> v1 的九类部件语汇（V1~V7）**作废**，替换为下面四条。

### 1.1 四条语汇

| # | 语汇 | 玩家侧原型 | Boss 侧画法（r = R_MAIN） |
|---|---|---|---|
| **V1** | **本体三层** | 暗底 + MAIN 实心 + 内框 | ① `DARK` 外壳 **×1.07**（体积感）→ ② **一块不透明 `MAIN` 实心**（×1.00）→ ③ `SEAM(0.45,0.49,0.57)` 内框描边 **×0.70 / 2px**。<br>**硬底线**：MAIN 实心块必须是一整块高饱和面积 —— 玩家靠它判断「该换哪件战甲」，切碎了就没有换甲读数 |
| **V2** | **三层三角尾焰** | 推进器：壳 + 外焰 + 焰心 | `STEEL` 喷嘴壳（`Rect2(x−1, −hw, 5, hw×2)`）→ `GLOW` 外焰三角（α0.45）→ `CORE` 焰心三角（α0.90，长 ×0.60）。<br>**恒在 +X 尾，绝不朝 −X**。焰长带 ~1.4 Hz 抖动（`1+0.12·sin(9t)`），守光敏线 |
| **V3** | **对称双菱形饰灯** | 绕身菱形光刃 | 舷侧一对菱形，`s = 0.055r`，中心 `(0.06r, ±0.38r)`，菱形高宽比 0.36，色 `CORE` α0.75。<br>Boss 侧**缩小成饰灯**，不做绕身轨道 —— 绕身光刃是玩家专属（§1.2 X4） |
| **V4** | **CORE 要害核** | —（Boss 专有） | `DARK` 眼窝（`cr + 0.07r`）→ `CORE` 芯（`cr = 0.20r + 1.6·pulse`）→ 纯白高光（`cr×0.42`）。<br>**恒在中轴偏 −X**（`ox ∈ [−0.58r, −0.10r]`），白核**必须完整包在眼窝+芯之内** |

### 1.2 禁用语汇（5 条，全路径）

| # | 禁用项 | 判据 | 理由 |
|---|---|---|---|
| **X1** | 🔴 **`Color(0.62,0.86,0.98)`（CANOPY）** | 数值精确匹配（`Game.gd:56`） | 玩家敌我识别主通道，铁律 |
| **X2** | **前向倾斜椭圆「座舱玻璃」形状 / 任何 ≥3 枚成阵的「窗」** | 形状判据 | v1 的「传感器阵列 / 舷窗列 / 观察缝」三个 CANOPY 替代方案**全部作废** —— Boss 不需要「窗」，要害核 V4 已经承担了「脸」的功能 |
| **X3** | **玩家同款绕身光刃**（`SWORD` 菱形轨道） | 形状判据 | 玩家专属攻击挂件；Boss 只留静态饰灯 V3 |
| **X4** | **玩家同款中心判定点**（`draw_circle(ZERO, 3.2, 白 0.95)`） | 位置 + 尺寸 | Boss 的白核只允许出现在 V4 的 DARK 眼窝内，且恒在 −X 偏移处 |
| **X5** | **玩家同款能量尾带**（10 点正弦 polyline，MAIN α0.5） | 形状判据 | 玩家专属；Boss 的「尾」只有 V2 三层三角焰一种表达 |

> **CANOPY 替代方案问题的终结**：v1 花了一整节（§1.3）论证「如何用非 CANOPY 色做窗」。
> v2 的答案是**不做窗** —— 少画一个部件比论证一个部件的合规性更省事，也不引入任何误读风险。

## 2 · 敌我识别

### 2.1 六条区分维度（按识别强度排序）

| # | 维度 | 玩家战甲 | Boss | 强度 |
|---|---|---|---|---|
| **1** | **体量** | 本体 40×22 px，判定 r11 | 直径 112~168 px（R_MAIN 56~84），**面积 ≥ 8 倍** | ★★★★★ |
| **2** | **轮廓朝向** | **+X 是头**（CANOPY 朝 +X） | **−X 是头**（CORE 要害核恒在 −X 偏移，+X 是三层尾焰） | ★★★★★ |
| **3** | **明暗关系** | **暗身亮边**：DARK 填充 + MAIN 描边 2.2px | **亮身暗边**：MAIN 大面积实心 + DARK 外壳 ×1.07 | ★★★★☆ 不依赖色相 |
| **4** | **是否带尾焰** | 无推进舱 | **有**：+X 三层三角焰（V2），五关恒在 | ★★★★☆ 二值判据 |
| **5** | **要害核形态** | 无（判定点是小实心圆） | **有**：DARK 眼窝 + CORE 芯 + 白高光三层（V4），且**只在 −X** | ★★★☆☆ |
| **6** | **双菱形饰灯** | 绕身轨道光刃（动） | 舷侧静态一对（不动） | ★★☆☆☆ 补强 |

> v1 的维度 4「拼装度（多片拼装 vs 一片）」与维度 6「告警条纹」**已删除** ——
> v2 的 Boss 本体就是「一块甲 + 一条内框」，与玩家同构，不再靠拼装度区分；
> 区分改由**维度 4「有没有尾焰」**承担（纯二值、不依赖颜色、远距离也成立）。

### 2.2 两个最坏场景的判据

| 场景 | 描述 | 三层判据（任一层成立即判敌） |
|---|---|---|
| **A · 远距离** | Boss 刚入场，屏幕右缘 x≈1150，玩家 x≈230 | ① **连续块面 > 100px**（玩家本体最长边仅 40px，**永不** > 100px）；② **尖/钝朝向**：尖头朝左（−X）= 敌；③ **右缘有尾焰** = 敌（玩家无推进舱） |
| **B · 弹幕高峰** | 同屏数百颗弹（r≈5~9）压在 Boss 上 | ① **连续实心面积 ≥ 112px**（弹幕是离散小球，形不成连续大面）；② **有没有冷青 CANOPY** —— 有 = 我，无 = 敌（全项目唯一被允许的颜色判据，且是「有/无」二值）；③ **+X 尾焰 / −X 要害核** 的朝向组合 |

> **v2 简化了 Boss 本体反而让判据 B① 更稳**：v1 的装甲片分块 + 接缝 + 铆钉会把主体切成小块，
> 02 §4.3 当时还专门写了「机甲化后必须复测 L2（对比 3.43:1，余量仅 14%）」。
> v2 本体是一整块 MAIN 实心，**等效大面积不再下降，这条复测取消**。

### 3.2 锚点坐标规则（三条）

1. **CORE 要害核**恒落在中轴偏 −X（`ox ∈ [−0.58r, −0.10r]`），**不得挪到 +X**。
2. **要害扇区 = −X ±40°**：除 CORE 与 CORE 自身的 DARK 眼窝外，**任何部件不得进入**。
   L3 炮列中轴留空、L4 触须基础角只在 +X 与 ±Y 半侧铺开，皆为此。
3. **尾焰**恒在 +X，焰尖不得超过 `1.30r`（越界会与护罩弧 ×1.70 抢焦点，也会撑爆
   剪影/碰撞比 1.19~1.22 的既有口径）。
