#### 1.1.4 硬约束（**改图前必读**）

1. **画布 44×36 绝不能改**（见 §4 红线）；**画布中心 (22,18) = 游戏内节点原点**，
   `Player.ROBE_TEX_POS = Vector2(-22,-18)` 是硬编码的对齐锚点，**运行时零 offset**。
2. **底部不透明行必须仍落在 y=35**（四色实测 bbox 底行均为 35）——
   否则 `ArmorArt.SHADOW_Y = 17`（18+17=35）的投影会浮空或陷入。
3. 越出剪影的内部元素一律与 `body` 掩膜求交（`ImageChops.darker`）；
   **但前伸的臂 / 炮管是向外伸出的，不能求交**（求交只会剩下与躯干重叠的部分）。
4. `shade = MAIN/DARK 的 0.55 混合`（`SHADE_MIX`），**不用纯 DARK**——
   纯 DARK 在深空底上几乎等于隐形，实测会让尾翼下端直接消失。

### 1.3 精英 84×84「星盗战将」· → **精英机 / 无人兵器**（用户已拍板 · **本次唯一重画资产 · v3 目标改为矢量 `PirateArt.draw_elite`**）

> 重定目标为**以原点为中心的矢量坐标**（−X 头 / +X 尾，与 `PirateArt` 现有语法同向）。

#### 1.3.1 核心矛盾与解法

我方战甲（人形装甲单兵）与星盗战将（精英机）**同为机械** → 原「生物 vs 机械」通道失效。
解法是把一个**语义事实**编码成**判别信息**：

> **无人兵器没有驾驶员 → 没有驾驶舱 → 没有 `CANOPY` 舱盖玻璃色。**
> **「有那块冷青玻璃 = 我；没有 = 敌」**

叙事上同样成立：星盗的精英机是**拼装的无人兵器**，而我方是**制式载人战甲**——
**制式 vs 拼装**的对立取代了**机械 vs 生物**。

矢量侧这一条**静态可校验**（§2.4 V1：扫描 `PirateArt.gd` 源码不得出现 CANOPY 色值），
这是「生物 vs 机械」做不到的事。

#### 1.3.2 敌我识别五条通道（精英机侧的具体落点 · 矢量坐标）

| 通道 | 我方战甲 | **精英机** | 在矢量精英机上的具体落点 |

| **② 朝向** | 朝右 | 朝左 | `CORE` 光学窗放 **x<0** 区（−X 半区），实测质心 **−15.77** |
| **③ 顶带轮廓** | 1 段（穹顶单峰） | **2 段** | **双联挂架**两座分离多边形，在探针行 `y=−30` 形成两段（实测 gap ≈ 28） |
| ④ 对称/非对称（加成） | 上下对称双炮管 | **单根下挂主炮** | 主炮 `rect(−36,4,−14,12)` 偏下偏前，与双挂架不等高共同造成非对称 |

#### 1.3.5 改图时的硬约束（**动了就会踩线**）

1. **挂架 / 部件最大半径 r ≤ 40**。法罡弧内缘在 43（`Elite.gd` 现有注释），
   造型最多探到 40，留 3px 呼吸。挂架若加长（顶点 r>40）会捅进法罡弧；
   若缩短到探针行以下，通道 ③ 失效。
2. **探针行 y=−30 必须切出 2 个有实宽的分离段**（实测 F 宽 6.5 / R 宽 8.0，gap 27.9）。
   两挂架若加粗到互相接触、或顶点恰好压在探针行上（单点退化），通道 ③ 立刻红。
3. **光学窗必须留在 −X 半区**（x ≤ −6）。实测质心 −15.77；若把光学窗移到机体中部/+X 区，
   朝向指针与要害读法同时失效。
4. **`CORE` 只用于光学窗**。若把 CORE 用到别处（如能量总线、肩沿），
   「唯一的 CORE 亮点 = 敌的目光」这个读法会被稀释，②通道随之失效。
5. **`draw_elite` 全函数禁止出现 CANOPY 色** `(0.62,0.86,0.98)`。⚠️ 特别当心
   `COLOR_GLOW[1]`（寒霜蓝 `(0.45,0.86,1.00)`）——它与 CANOPY 的 **G 分量完全相同
   （0.86）、B 只差 0.02**（8-bit 下 250 vs 255 = 5），肉眼在深空底上分不开。
   静态检查（§2.4 V1）必须**三通道同时匹配**，绝不能写成「任一通道命中」。
6. **独立重绘，绝不复用小妖 ×1.7**（沿用原纪律：整数放大小妖剪影会被读成
   「一群小无人机」，且失去底盘级差异）。

#### 1.3.6 沿用纪律

- 属性识别仍**只靠颜色**；主炮形状不随属性变化（若要风味件，可让挂架尖端按属性微调，
  属可选）。
- 描边沿用 `PirateArt` 的 `_outline(…, dk, 5.0)`（DARK 体壁描边），不引入新色相。
- **角/挂架必须用 GLOW**（最亮档）——用 MAIN 会与躯干同亮度糊成一团。
- 动画沿用 `breath()` / `tail_jitter()` 两种，**禁止整体旋转、缩放 >8%、主体轮廓顶点抖动**
  （`PirateArt` 头部注释铁律原样适用）。

## 6 · 精英机方案下的残余风险（**供 quality-lead 实机取帧重点核对**）

### 6.1 🔴 高：主通道的物理尺寸太小

- **事实**：`CANOPY` 舱盖只有约 **50 px**（玩家 FACE 区域 7×5 上下）。
  在 1280×720 视口里，玩家本体 44×36，舱盖约占其 **3%** 面积。
- **风险**：「有 / 无那块冷青玻璃」在**高速弹幕中的余光读取**下可能丢失。
  断言 H 能保证像素层存在，**保证不了玩家看得见**。
- **取帧核对**：玩家与精英机**同屏、相距 200~400px、屏幕快速滚动**时截图，
  问一句「不看颜色说明，你能立刻指出哪个是自己吗？」

  1. 把舱盖面积从 ~50px 扩到 ~80px（把 FACE 从 `(25,11,3,4)` 扩到 `(25,11,4,6)`，
     **几何微调、断言 H 阈值同步提到 ≥70**）；
