## D. 存档品阶串迁移方案

**现状**：`user://highscores.json` 结构
```json
{ "0": {"score": int, "robes": [int,int], "rank": "天品·元婴", "win": bool}, ... }
```
- 键是难度 int 转 String（`"0"/"1"/"2"`）——**不动**。
- `"robes"` 存 `Array[int]`（0/1/2/3）——**不动**，与新题材兼容（颜色枚举值未变）。
- `"rank"` 存旧品阶串（如 `"天品·元婴"`）——**文案已改**，旧串将不再产生。

**问题**：改文案后，旧存档里已存的 `rank` 仍是旧串。结算界面 `ResultScreen._rank()` 读的是**本局实时** `Game.rank_of(score)`（新串），不受影响；但存档中历史 `rank` 字段在下次刷新前仍是旧串。

**处理建议（推荐方案 1）**：

1. **方案 1 · 旧串原样显示，不做迁移（推荐）**
   - `rank_of()` 只影响新结算。旧存档的 `rank` 字段当前**没有任何界面读取展示**（ResultScreen 显示的是实时 `_rank()`，历史最高只显示分数 `result_prev_high`，不显示历史 rank 串）。
   - 结论：**旧 rank 串实际不展示给玩家**，无需迁移，零风险。只需保证 `rank_of()` 返回新串即可。
   - 建议在 `save_highscore()` 注释补一句「rank 为展示串，随文案版本变化，不承担跨版本兼容职责」。

2. **方案 2 · 一次性映射（仅当未来要展示历史 rank 时才需要）**
   - 加一个 `_migrate_rank(s: String) -> String`，把旧四串映射到新四串：
     `天品·元婴→金勋·星帅`、`地品·金丹→银勋·星将`、`玄品·筑基→铜勋·星尉`、`黄品·炼气→铁勋·星兵`。
   - 在 `_load_highscores()` 里对每条 `d["rank"]` 过一遍映射并回写。
   - 当前无展示需求，**暂不实施**，留作可选。

> 我（文策渊）建议采用**方案 1**：因为经代码核实，历史 rank 串从未在任何界面被读取展示，迁移是无用功。此结论请 quality-lead 复核「确无界面读 `highscores[key]["rank"]` 展示」。
