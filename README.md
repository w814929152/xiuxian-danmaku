# 弹幕修仙

Godot 4 横版修仙弹幕射击（Shoot 'em up）。零美术资源，全部图形由 GDScript `_draw()` 手绘。

## 运行

**最快方式**：双击 `运行游戏.bat`（自动查找 Godot，直接进游戏，不打开编辑器）。

三个 bat 的区别：

| bat | 用途 |
| --- | --- |
| `运行游戏.bat` | 从源码跑，自动找 Godot（改代码后立刻生效） |
| `运行自测.bat` | headless 跑 134 项断言（优先找控制台版 Godot） |
| `运行导出版.bat` | 启动 `build/弹幕修仙.exe`（打包版，不含未重导的最新改动） |

三个 bat 均按以下顺序找 Godot：`GODOT_EXE` 环境变量 → bat 同目录 → 常见安装位置 → `PATH`。
找不到时会提示三种指路方式，不再要求手改路径。

> ⚠️ 这三个 bat 必须是 **CRLF 换行 + GBK 编码**。纯 LF 换行会让 cmd 解析错乱 ——
> `set` 不生效、中文行的碎片被当成命令执行（表现为一堆「不是内部或外部命令」）。
> 用 VS Code 改完记得看右下角是否仍是 `CRLF`，编码是否仍是 `GBK`。

手动方式：

1. 安装 **Godot 4.2+**（推荐 4.2 / 4.3 / 4.4 标准版，非 .NET 版）
2. 打开 Godot → `Import` → 选择本目录下的 `project.godot`
3. 首次打开会自动导入 `fonts/simhei.ttf`（中文显示用，约需几秒）
4. 按 `F5` 运行

> 已在 **Godot 4.7.2.stable** 上实机验证：资源导入、主场景启动、全流程运行均 0 报错。

> 中文字体：`project.godot` 里已把默认字体设为 `res://fonts/simhei.ttf`（从系统复制的 simhei）。
> 若不想打包字体，删掉该行即可，代码会自动回退到 `SystemFont`（微软雅黑 / SimHei）。

## 开始界面

启动后进入开始界面，三项主菜单：

| 项 | 入口 | 内容 |
| --- | --- | --- |
| **开始游戏** | `Enter` / 数字键 `1` | 进入**择难度**（三选一），再进择道袍界面（四选二），选满两件后入关 |
| **道袍库** | `↓` 后 `Enter` / 数字键 `2` | 逐件翻阅四件道袍：立绘、免疫属性、神通、来历详述 |
| **游戏说明** | 数字键 `3` | 操作、四色规则、符光与过热、破罩之法、计分 |

道袍库与说明界面按 `ESC` / `Enter` 返回开始界面；择难度界面按 `ESC` 返回开始界面，
择道袍界面按 `ESC` 退回择难度。

## 三档难度

开始游戏后先择难度（默认停在**普通**）。三档只在**血魔老祖**身上分高下 —— 妖潮一视同仁：

| | 简单 | 普通 | 困难 |
| --- | --- | --- | --- |
| 老祖元神 | **1000** | **2500** | **3600** |
| 法相 | **两重**（50%） | 三重（67% / 34%） | 三重（67% / 34%） |
| 属性法罩 | **无** | **无** | **有** |
| 异色伤害 | 100% | 100% | **衰减到 60%** |
| 弹幕密度 | **55%** | **80%** | 100% |
| 狂暴 | 血量三成时 | 血量三成时 | 血量三成时 |

"弹幕密度"是同一个系数管两件事：既拉长套路的发射间隔（`TICK / k`），也收缩一次齐射的弹数
（`_n(base)`，至少 1 发）。小妖的出手间隔同样按它放慢（`fire_cd *= 2 - k`），
所以简单档的妖潮也明显更稀。

> 参数集中在 `Game.gd` 的五个访问器里（`boss_hp` / `boss_phases` / `boss_ward` /
> `bullet_scale` / `off_color_mul`），`Boss._ready()` 只取一次就不再查全局。
> 写成带返回类型的函数而不是一张配置表，是为了让调用点直接拿到 `int` / `bool` / `float`，
> 不必到处写 `int(cfg["boss_hp"])` 这种下标取值。

## 四色规则

| 道袍 | 免疫 | 被动 |
| --- | --- | --- |
| 赤炎剑袍（红） | 免疫**赤炎**弹 | 攻击化为**双排飞剑**（8 × 2） |
| 玄冰遁袍（蓝） | 免疫**玄冰**弹 | 移动速度 **+50%**（340 → 510） |
| 太清罡袍（白） | 免疫**太清**弹 | **10 点罡气护盾**；连续 **10 秒未受伤**护盾回满 |
| 戊土符袍（黄） | 免疫**戊土**弹 | 攻击化为**持续符光**（激光 120 DPS），带**过热**机制 |

补充规则：

- 被免疫的同色弹会**穿过**玩家并泛起光环，不会打断"十息回气"计时。
- 罡气护盾是数值资源，但**只在太清罡袍（白）下生效**；换袍后数值保留，换回来继续用。
- 玩家飞剑颜色 = 当前道袍颜色。小怪受到**同色**飞剑伤害 **+50%**（同源共振）。

### 戊土符袍 · 符光过热

按住开火键出**一道绵绵不绝的符光**（不是弹丸，按 0.2 秒一跳结算伤害给光柱上的一切目标）。
代价是符袍生热：

| 事件 | 过热值变化 |
| --- | --- |
| 出光 | 每秒 **+20** |
| 过热值到 **100** | 立刻**无法出光**，须停手 |
| 停火满 **0.5 秒**后 | 每秒 **−30** |
| 触及一发**戊土（黄）弹** | 立刻 **−30** |

过热是**带闭锁**的：满 100 之后必须一直散到 **60** 以下才能重新出光。
这不是多加的规则 —— 若一到 99 就解锁，按住不放会卡进「锁 0.5 秒 → 亮 1 帧 → 再锁」的抖动
（升温 20/s 远快于每帧的散热量，占空比只剩约 5%），符光等于废掉。加了这道闸门，
按满一轮的代价是约 1.8 秒停手 —— 而硬吃一发戊土弹能省下其中 1 秒，这就是戊土符袍的独门节奏。

HUD 左上角有对应的过热槽，玩家身上的过热环也会随值涨满；闭锁期间转红并显示「符袍过热 · 停手散热」。

> 注：需求里"蓝色皮肤：免疫红色魔法弹"应为笔误，已按对称设计实现为**免疫蓝色弹**。
> 若确实要免疫红色，改 `scripts/entities/Player.gd` 的 `take_hit()` 中 `if c == color:` 一行即可
> （改成先查表：`if c == IMMUNE[color]`，`IMMUNE = [RED, RED, WHITE]`）。

## 漂浮道具

斩妖有概率掉落（**18%**，N=2000 实测 18.65%），每一重妖潮结束再额外刷新 **1** 个
（散落在场景右段，逼玩家挪过去）。道具随场景向左漂，约 15 秒后淡出。

每局合计约 **3.6（斩妖）+ 3（三波）≈ 6~7 个**。两个来源里「固定送的」只占不到一半 ——
早先是每波刷 2 个，固定送的占了大半，反而把「斩妖出不出货」稀释掉了，所以收到 1 个。

| 道具 | 效果 |
| --- | --- |
| **回春丹** | 回复元神 **20** 点（满血时拾取会被浪费） |
| **剑影符** | 弹道 **+1 排**（最多再叠 3 层）；戊土符袍改为**多一道符光**，且**不额外增加过热值** |
| **增攻符** | 攻击力 **+30%**（最多叠 4 层）；飞剑变大、符光变粗 |
| **无量罩** | **6 秒无敌**，周身泛起四色流转的护罩 |

几条设计上的取舍：

- **排数是「道袍基准 + 剑影符层数」**：赤炎剑袍基准双排、其余单排、戊土是一道符光。
  排数越多齐射铺得越开，间距随排数收窄、最多铺到 ±50，不会飞出屏幕。
- **增攻符同时是数值与视觉的**：伤害 ×(1 + 0.3 × 层数)，飞剑整节点放大（碰撞体一起变大），
  符光加粗。只把数字调大、样子不变，玩家是感觉不到自己变强的。
- **剑影符对戊土只加符光道数，发热速度不变** —— `_update_heat()` 只认「是否在出光」这一件事，
  加排只加伤害。否则戊土符袍吃了剑影符会瞬间过热，道具反倒成了惩罚。
- **无量罩与受击无敌帧是两套计时**，互不干涉；罩生效期间不会被打断「十息回气」。

## 护法妖将（精英怪）

第 **2、3** 重妖潮的小妖清完后，各有一只**护法妖将**压轴登场（横幅提示），斩了才放行进下一重。
它身披一层**属性法罡**，可以理解为「会走位的老祖法罩」：

| 阶段 | 行为 |
| --- | --- |
| 法罡存续 | 同色飞剑全额（并享同源共振 +50%），异色只剩 **35%**；**法罡不破，本体一点不掉血** |
| 破罡虚弱（4.5 秒） | 移速减半、出手放慢、本体**任意颜色全额** —— 全力输出的窗口 |
| 虚弱结束 | **重铸法罡**（共 2 层，用完即永久破防） |

- 法罡色**只从玩家已选的两件道袍中抽取**（同老祖的法罩）。这不只是机制复刻，
  而是可行性要求 —— 凭空给个玩家没带的颜色，破罡就成了死局。
- 斩杀奖励 **+800**，且**必掉一件道具**；本体元神 480、单层法罡 150，都按波次系数缩放
  （第 2 重 552 / 172，第 3 重 624 / 195）。
- 外观：四色小妖 sprite 放大 + 矢量法罡环，头顶双条（上法罡、下本体）+ 身份名。
- **新增可受击目标时零成本**：Sword 只认 `Damageable`，Elite 继承它就自动被飞剑命中。

## 关卡结构

```
开始界面 → 择难度 → 择道袍（四选二）→ 第 1 重妖潮(5) → 第 2 重(7)+妖将
        → 第 3 重(8)+妖将 → 血魔老祖
```

波次结束**不再回血** —— 元神只靠回春丹补。

### Boss：血魔老祖

血量 / 法相数 / 法罩见上表。简单档只有两重法相（50% 一线），普通与困难是三重（67% / 34%）。

- **属性法罩**（仅困难）：周期性展开法罩（色从玩家已选的两件道袍中抽取）。法罩开启时，
  **只有同色飞剑造成 100% 伤害，其余颜色衰减到 60%** —— 这是逼迫玩家在战斗中换袍的核心机制。
  简单 / 普通不展法罩，全力输出即可。
- **第 1 重法相**：赤炎扇射（11 向）、玄冰三连狙、赤炎灵雨
- **第 2 重法相**（≤67%）：太清环形弹（24 向）、冰火双螺旋、玄冰灵雨（追踪）、戊土符扇（7 向）
- **第 3 重法相**（≤34%，简单档无）：四色乱舞、戊土符雨、追踪弹幕，弹幕频率与 Boss 移动速度提升
- 每次换阶段：全屏清弹 + 冲击波 + 法罩重置

### 狂暴（三档共有）

老祖元神跌破**三成**时狂暴，与难度无关：

- 周身泛起**血红光晕**，脉动的血色符环 + 十颗逆向游走的血色符点
- **屏幕四周泛起血光**（HUD 绘制）：缓慢呼吸 + 每 **1.8 秒**一次心跳尖峰，
  刚进狂暴的那一下再来一次**爆闪**（约 0.75 秒衰减）——
  「局面变了」这个信号一帧就能读到，不靠横幅
- 额外叠加**四色螺旋弹幕**：四条旋臂各占一色（赤炎 / 玄冰 / 太清 / 戊土），
  同角速度向外卷，每 `0.09s`（会再按弹幕密度放慢）转过 0.40 弧度发一轮
- 狂暴是一次性的（不解除、不重复触发），横幅提示「狂 暴」，HUD 的血条标题转红并标注 `· 狂 暴`
- 这层螺旋与当前法相的套路**并行**发射，所以困难档狂暴后是「法罩 + 套路 + 螺旋」三重压力

> 自测里所有"等一会儿"的地方都**轮询状态**而不是数帧：
> `for _i in 400: if b._st == "fight": break; await process_frame`。
> headless 下帧率约 140fps 且抖动很大，「等 200 帧」换算不出稳定的游戏时间，
> 数帧的写法在实机上一改帧率就假通过了。

> 后半句不是套话。GDScript 里没法从脚本侧捕获 `push_error`，而 Godot 在赋值校验失败时
> 是**跳过赋值**而不是让坏值落下去 —— 所以像「把已释放对象赋给弹幕 target」这类缺陷，
> 断言反而会通过，只有日志里的 `ERROR` 会暴露它。跑完务必看一眼日志。

> 坑记录：Godot 的 `Input.action_press()` 只改输入状态、不派发事件，UI 的
> `_unhandled_input` 收不到。自测中用 `Input.parse_input_event(InputEventAction)` 走真实输入通道。

## 导出 exe

前置：本机**装过与本引擎版本完全一致的导出模板**（4.7.2.stable），
位置 `%APPDATA%\Godot\export_templates\4.7.2.stable\windows_release_x86_64.exe`。
模板不在项目里、也不随 Godot 附带，需单独下载（`*_export_templates.tpz`，解压后把
`templates/windows_release_x86_64.exe` 放到上述目录即可，无需整包解压）。

导出配置已写好（`export_presets.cfg`，预设名 `Windows Desktop`）：

```
Godot_console.exe --headless --path <项目目录> --export-release "Windows Desktop"
```

产物是 `build/弹幕修仙.exe` 单文件（**110 MB**，`embed_pck=true`，资源已打进 exe，可直接分发）。
预设里排除了 `_selftest/`、`_capture/`、`tools/` —— 那是开发与取帧用的，不属于游戏。

> **导出路径的目录必须先存在**，Godot 不会自动创建，否则报
> `准备模板: 给定的导出路径不存在`。

体积构成：**模板 exe 104 MB**（固定开销）+ 游戏资源约 6 MB。
`fonts/simhei.ttf`（9.3 MB）是 `theme/custom_font`，也是 `DrawUtil.font()` 的加载目标，
去掉界面会全变方块 —— 别动它。要进一步瘦身只能做字体子集化（只留界面用到的字）。

> 已清理：`fonts/` 下原本还有 `msyh.ttc`(18.8 MB) 与 `simkai.ttf`(11.2 MB)，
> 全项目无任何引用（只有 `simhei.ttf` 被用到），却会被打进包 —— 去掉后
> **131 MB → 110 MB**。两者都是 Windows 系统字体，需要时可从 `C:\Windows\Fonts` 取回；
> 本项目也留了副本在 `D:\demo\_unused_fonts_backup\`。
> 教训：**导出前先按包内清单扫一遍大文件**，字体这类"放进去就被无条件打包"的资源最容易堆积。

首次导出前装模板（只需一次，约 200 MB，不必整包解压 1.28 GB）：

```
# 1) 下载整包（1.28 GB）
https://github.com/godotengine/godot/releases/download/4.7.2-stable/Godot_v4.7.2-stable_export_templates.tpz
# 2) 只取 Windows 两个模板，放到 %APPDATA%\Godot\export_templates\4.7.2.stable\
tar -xf templates.tpz -C <临时目录> templates/windows_release_x86_64.exe templates/windows_debug_x86_64.exe
```

验证打包内容（不必真的双击 exe —— 引擎可直接加载嵌入的 pck）：

```
Godot_console.exe --headless --main-pack "build/弹幕修仙.exe" --quit-after 300
```

> 若本机启用了**应用程序控制策略**（AppLocker / WDAC），未签名的 exe 会被拒绝启动
> （`应用程序控制策略已阻止此文件`），这与导出是否成功无关 —— 换台机器或让管理员放行即可。
> 个人电脑上更常见的是 SmartScreen 首次警告，点「更多信息 → 仍要运行」即可。
