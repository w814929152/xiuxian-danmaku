# 星际弹幕

Godot 4 横版**太空歌剧 · 星舰**弹幕射击。零美术资源，全部图形由 GDScript `_draw()` 矢量手绘。

## 运行

**最快方式**：双击 `运行游戏.bat`（自动查找 Godot，直接进游戏，不打开编辑器）。

三个 bat 的区别：

| bat         | 用途                                  |
| ----------- | ----------------------------------- |
| `运行游戏.bat`  | 从源码跑，自动找 Godot（改代码后立刻生效）            |
| `运行自测.bat`  | headless 跑自动化冒烟测试（优先找控制台版 Godot）    |
| `运行导出版.bat` | 启动 `build/弹幕修仙.exe`（打包版，不含未重导的最新改动） |

三个 bat 均按以下顺序找 Godot：`GODOT_EXE` 环境变量 → bat 同目录 → 常见安装位置 → `PATH`。  
找不到时会提示三种指路方式，不再要求手改路径。

> ⚠️ 这三个 bat 必须是 **CRLF 换行 + GBK 编码**。纯 LF 换行会让 cmd 解析错乱 ——  
> `set` 不生效、中文行的碎片被当成命令执行（表现为一堆「不是内部或外部命令」）。  
> 用 VS Code 改完记得看右下角是否仍是 `CRLF`，编码是否仍是 `GBK`。

手动方式：

1. 安装 **Godot 4.2+**（推荐 4.2 / 4.3 / 4.4 标准版，非 .NET 版）
2. 打开 Godot → `Import` → 选择本目录下的 `project.godot`
3. 首次打开会自动导入 `fonts/simhei.ttf`（中文显示用，约需几秒）
4. 按 `F5` 运行

> 已在 **Godot 4.7.2.stable** 上实机验证：资源导入、主场景启动、全流程运行均 0 报错。

> 中文字体：`project.godot` 里已把默认字体设为 `res://fonts/simhei.ttf`（从系统复制的 simhei）。  
> 若不想打包字体，删掉该行即可，代码会自动回退到 `SystemFont`（微软雅黑 / SimHei）。

> 导出产物文件名仍是旧题材的 `弹幕修仙.exe`（写在 `export_presets.cfg` 与 `运行导出版.bat` 里），  
> 尚未随题材改名。改名要动这两个文件，与本文档无关 —— 这里照实写，免得按 README 找不到 exe。

## 操作

| 按键               | 功能                              |
| ---------------- | ------------------------------- |
| `W A S D` / 方向键  | 移动                              |
| `J` / `K` / 鼠标左键 | 开火（按住连发）                        |
| `空格`             | 换甲（在择定的两件战甲间循环，0.2 秒冷却）         |
| `P` / `ESC`      | 暂停                              |
| `R`              | 重来本关                            |
| `T`              | 结算界面「换甲再来」（保留当前关卡，直接回择甲界面）      |
| `N`              | 结算界面「下一关」（仅通关且下一关已解锁时可用）        |
| `1` `2` `3`      | 开始界面直达：开始出征 / 战甲库 / 作战手册（也可鼠标点） |
| `1` … `5`        | 选关界面直达第 1~5 关                   |
| `1` `2` `3` `4`  | 择甲界面点选四件战甲                      |
| `↑` `↓`          | 开始界面选择菜单项                       |
| `←` `→`          | 选关界面左右切换                        |
| `Enter`          | 确认；`ESC` 返回上一级                  |

## 五关星域

开始出征后先选关（默认停在当前关；当前关没解锁就停在已解锁的最后一关）。  
**通关一关即解锁下一关**，锁态同时给出「斜封条 + 锁形」和「未解锁 / 通关第 N-1 关开启」两条冗余提示。

| 关  | 星域 / 副题      | 关底旗舰        | 波数 | 精英数 | 旗舰装甲 | 阶段 | 护罩模式              | 异色伤害 | 弹幕密度 | 狂暴线 | 分数倍率  | 满分    |
| -- | ------------ | ----------- | -- | --- | ---- | -- | ----------------- | ---- | ---- | --- | ----- | ----- |
| L1 | 锈带星域 · 初次交火  | 熔核号 · 星盗先驱  | 3  | 1   | 1600 | 2  | 全程轮转              | 60%  | 0.55 | 30% | ×1.00 | 8850  |
| L2 | 霜环星域 · 双色夹击  | 霜噬号 · 星盗旗舰  | 4  | 2   | 2400 | 3  | 无                 | 100% | 0.80 | 30% | ×1.10 | 12705 |
| L3 | 耀斑星域 · 列阵轰击  | 耀斑号 · 星盗炮垒  | 4  | 3   | 3200 | 3  | 无（常驻减伤 70% + 散热期） | 100% | 0.85 | 30% | ×1.20 | 14880 |
| L4 | 引力井星域 · 深渊回响 | 深渊之喉 · 星盗母舰 | 5  | 3   | 4200 | 3  | 仅暴露期展开（子核心机制）     | 60%  | 0.95 | 30% | ×1.30 | 18720 |
| L5 | 王座星域 · 终局    | 终焉号 · 星盗王   | 5  | 4   | 6000 | 4  | 全程轮转              | 55%  | 1.00 | 25% | ×1.40 | 23940 |

> 「精英数」是本关压轴精英的**总只数**（四类精英的分关分配见「精英怪」一章）。  
> 满分 `_MAX` 是按波次表重算出来的落账满分，不是估算 —— 精英只数一变，它就得跟着重算，  
> 否则实际可得分会超出满分 100%，金勋线（96%）就白送了。

"弹幕密度"是同一个系数管两件事：既拉长套路的发射间隔（`TICK / k`），也收缩一次齐射的弹数  
（`_n(base)`，至少 1 发）。星盗的出手间隔同样按它放慢（`fire_cd *= 2 - k`），  
所以 L1 的星袭也明显更稀。

掉落率也逐关：L1~L4 击杀掉落 **18%**，L5 收到 **14%**（终局的续航考验）。

> 参数全集中在 `scripts/StageCfg.gd`，对外**只暴露带返回类型的静态访问器**  
> （`boss_hp()` / `boss_phases()` / `bullet_scale()` / `off_color_mul()` / `score_multiplier()` …）。  
> 写成函数而不是一张配置表，是为了让调用点直接拿到 `int` / `bool` / `float`，  
> 不必到处写 `int(cfg["boss_hp"])` 这种下标取值 —— `Variant` 退化是这套代码踩过的最大的坑。  
> 另一个坑：`const` 里不能放 `Dictionary` / `Array` 的复杂结构，也不能放  
> `PackedStringArray([...])`（需要在 `static func` 里构建），且**表里元素类型必须同构**，  
> 否则推断不出 `Array[int]`。所以波次级表是「5 关 × 5 波」展平的一维表，不足的格子填 0。

## 四色规则

| 战甲      | 免疫        | 被动                                                      |
| ------- | --------- | ------------------------------------------------------- |
| 电浆剑甲（红） | 免疫**电浆**弹 | 攻击化作 **双排光刃**（8 × 2）                                    |
| 寒霜疾甲（蓝） | 免疫**寒霜**弹 | 吸收一枚寒霜弹 → **闪避 0.5 秒**；移动速度 **+50%**（340 → 510）；单排光刃 10 |
| 光子盾甲（白） | 免疫**光子**弹 | 吸收一枚光子弹 → **护盾 +10**；**护盾上限 20，开局为 0，不再自动回复**           |
| 引力束甲（黄） | 免疫**引力**弹 | 攻击化作 **持续引力束**（120 DPS），带**过热**机制                       |

补充规则：

- 被免疫的同色弹会**被吸收并消失**（不是穿过去），周身泛起一圈向内收束的光环 —— 读作「吸入」。  
  穿光子盾甲（白）时，吸收一枚光子弹还会为**护盾充能 +10**。
- 护盾开局为 **0**，上限 **20**，**不再自动回复**（唯一的充能入口就是上面那条）；且**只在光子盾甲（白）下减伤**，  
  换甲后数值保留，换回来继续用。
- 玩家光刃颜色 = 当前战甲颜色。星盗受到**同色**光刃伤害 **+50%**（同源共振）。
- 敌方能量弹**四色同形**：共用一张 24×24 白模纹理，运行期 `modulate` 染成属性色。  
  形状统一、只靠颜色区分属性 —— 四色异形在弹幕高峰时会让画面过于杂乱。  
  视觉半径 12 > 碰撞半径 9（擦弹余量 1.33）：**视觉大于判定是初版手感的一部分**，别"顺手优化"成所见即所中。

### 引力束甲 · 引力束过热

按住开火键出**一道绵绵不绝的引力束**（不是弹丸，按 0.2 秒一跳结算伤害压在光柱上的一切目标）。  
代价是发生器生热：

| 事件             | 过热值变化          |
| -------------- | -------------- |
| 出束             | 每秒 **+20**     |
| 过热值到 **100**   | 立刻**无法出束**，须停手 |
| 停火满 **0.5 秒**后 | 每秒 **−30**     |
| 触及一发**引力（黄）弹** | 立刻 **−30**     |

过热是**带闭锁**的：满 100 之后必须一直散到 **60** 以下才能重新出束。  
这不是多加的规则 —— 若一到 99 就解锁，按住不放会卡进「锁 0.5 秒 → 亮 1 帧 → 再锁」的抖动  
（升温 20/s 远快于每帧的散热量，占空比只剩约 5%），引力束等于废掉。加了这道闸门，  
按满一轮的代价是约 1.8 秒停手 —— 而硬吃一发引力弹能省下其中 1 秒，这就是引力束甲的独门节奏。

HUD 左上角有对应的过热槽，玩家身上的过热环也会随值涨满；闭锁期间转红并显示「束甲过热 · 停手散热」。

> 散热那段（`Player.take_hit()` 里「触及引力弹 → `heat -= 30`」）**必须排在同色免疫判定之前**。  
> 引力弹现在会被吸收并消失，如果先走免疫分支 `return`，穿引力束甲的玩家就再也吃不到这 −30 的散热 ——  
> 沉默的回归，自测断言也测不出来（数值没变，只是再也不降）。

## 漂浮道具

斩敌有概率掉落（**18%**，L5 为 **14%**，N=2000 实测 18.65%），每一波星袭结束再额外刷新 **1** 个  
（散落在场景右段，逼玩家挪过去）。道具随场景向左漂，约 15 秒后淡出。

每关合计约「斩敌 3~4 个 + 每波 1 个」（波数随关卡 3 → 5 递增）。两个来源里「固定送的」只占一半左右 ——  
早先是每波刷 2 个，固定送的占了大半，反而把「斩敌出不出货」稀释掉了，所以收到 1 个。

| 道具       | 效果                                                   |
| -------- | ---------------------------------------------------- |
| **修复包**  | 回复生命 **20** 点（满血时拾取会被浪费）                             |
| **刃影模块** | 弹道 **+1 排**（最多再叠 3 层）；引力束甲改为**多一道引力束**，且**不额外增加过热值** |
| **增幅核心** | 攻击力 **+10%**（最多叠 4 层，封顶 +40%）；光刃变大、引力束变粗              |
| **力场罩**  | **6 秒无敌**                                            |

几条设计上的取舍：

- **排数是「战甲基准 + 刃影模块层数」**：电浆剑甲基准双排、其余单排、引力束甲是一道引力束。  
  排数越多齐射铺得越开，间距随排数收窄、最多铺到 ±50，不会飞出屏幕。
- **增幅核心同时是数值与视觉的**：伤害 ×(1 + 0.1 × 层数)，光刃整节点放大（碰撞体一起变大），  
  引力束加粗。只把数字调大、样子不变，玩家是感觉不到自己变强的。
- **刃影模块对引力束甲只加束的道数，发热速度不变** —— `_update_heat()` 只认「是否在出束」这一件事，  
  加排只加伤害。否则引力束甲吃了刃影模块会瞬间过热，道具反倒成了惩罚。
- **力场罩与受击无敌帧是两套计时**，互不干涉。
- 道具**不走对象池**：一局只掉十来个，池化收益为零，反而多一层 reset 要维护。  
  但生成必须延后一帧 —— 掉落常常发生在**物理回调里**（光刃命中 → `Enemy._die()` → 掉落），  
  那时新建 `Area2D` 并改碰撞层会报 `Can't change this state while flushing queries`。  
  **别在物理回调里动碰撞体**，这条规矩和弹幕 / 光刃归还时一致。

## 精英怪（四类）

星袭的中前段与末段波次会有精英**压轴**登场（横幅提示），斩了才放行进下一波。  
原本只有一只「星盗战将」，现在扩成**基类 `EliteBase` + 四个子类**，机制刻意互补 ——  
每关的主考仍是战将（换甲），新三只分别考弹幕走位、清场决策、走位绕背。

| 子类            | 名称（`EnemyKind.ELITE_CN`） | 考什么         | 机制                                                                              | 血量              | 斩杀   |
| ------------- | ------------------------- | ----------- | ------------------------------------------------------------------------------- | --------------- | ---- |
| `Elite`       | 星盗战将 · 破罩精锐              | **换甲**      | **属性力场** 2 层：同色全额（并享共振 +50%），异色只剩 **35%**，**力场不破本体一点不掉血**；破力场进虚弱 **4.5 秒**（移速减半、出手放慢、任意色全额），虚弱结束**重铸**，用完即永久破防 | 480 + 力场 150/层   | 800  |
| `EliteBastion` | 弹幕堡垒将 · 移动炮台             | **弹幕走位**    | 缓慢逼近的厚甲炮台，双层错相环（外圈 12 发自转 / 内圈 6 发反转）织成「墙」，缝隙一直在动、不能站桩；**无护罩，任意色全额打**           | 900             | 900  |
| `EliteSwarm`  | 增殖指挥将 · 召唤母舰             | **清场优先级**   | 每 **4.5 秒**召唤 **2 只同色喽啰**（硬闸 6），本体躲在召唤物后面；**每次召唤自愈 2%**。忽视清场就会一直被喽啰消耗        | 620             | 900  |
| `EliteAegis`  | 护盾冲锋将 · 朝向重甲             | **走位绕背 + 换甲** | 正面挂一面**朝向护盾**（朝左锥形，半角 **55°**）：锥内命中全打在护盾上，**绕到侧 / 背才打得到本体**；会冲锋（移速 ×2.4，间隔 3.2 秒） | 720 + 护盾 260（1 层，破盾虚弱 4 秒） | 900  |

几条铁律与设计取舍：

- **可行性铁律（四只通用）**：任何**必须特定颜色才能破**的色防，其色只从玩家已选的两件战甲 S 抽 ——  
  战将的力场色、冲锋将的护盾色、指挥将的召唤色，无一例外。凭空给个玩家没带的颜色，破防就成了死局。  
  **那不是难度，是设计事故。**
- 堡垒将**没有必须打破的色防**：它没有护罩，换同色甲只是「省力」（吸收弹幕）而非「活命」，不换也能硬躲 ——  
  它考的是纯 DPS + 弹幕走位。
- 冲锋将的朝向护盾是**「绕背」机制，不是「破罩」**：不换甲也能靠走位打本体，只是更慢。  
  这条通道让它不至于变成第二个战将。
- 斩杀**必掉一件道具**；血量都按波次系数缩放（`StageCfg.wave_hp_scale()`）。

### 分关分配（`StageCfg._ELITE_TYPE`）

| 关  | 精英编排                                            | 总数 |
| -- | ----------------------------------------------- | -- |
| L1 | 战将（第 3 波）                                       | 1  |
| L2 | 指挥（第 2）· 战将（第 4）                                | 2  |
| L3 | 堡垒（第 2）· 战将（第 3、4）                              | 3  |
| L4 | 冲锋（第 2）· 战将（第 4、5）                              | 3  |
| L5 | 堡垒（第 2）· 指挥（第 3）· 战将（第 4、5）                     | 4  |

- **战将的位置完全不动**（仍是 L1-3 / L2-4 / L3-3,4 / L4-4,5 / L5-4,5）—— 它最贴合「换甲」这根支柱，是每关的主考。
- 新三只作为**额外**精英插在中前波，且**不与战将同波**：一波塞两种色防机制，玩家读不过来（认知过载）。
- L1 保持**单战将**：教学关，机制不宜过早叠。
- **同关两只战将强制异色**（L3 第 3/4 波、L4 第 4/5 波、L5 第 4/5 波），否则同一套双甲会把两场压轴打成同一道题。

### 战将弹幕多色化（`StageCfg._ELITE_HUE`）

战将弹幕原本清一色是力场色（∈ S）。玩家换上同色甲后弹幕被**全量吸收**（寒霜疾甲闪避 / 光子盾甲充盾），  
战将的弹幕威胁**归零** —— 「破罩」与「走位」只活了前半。现在按关掺色：

| 关  | 色数 | 说明                                    |
| -- | -- | ------------------------------------- |
| L1 | 1  | 恒单色（教学期不该一上来就混色，与 `bullet_scale` 的递进语言一致） |
| L2 | 1  | 恒单色                                   |
| L3 | 2  | 掺 1 路骚扰色                              |
| L4 | 3  | 掺 2 路骚扰色                              |
| L5 | 4  | 掺 2 路骚扰色 + 玩家的副甲色                     |

- 色序 = `[力场色, S'①, S'②, S 另一色]` 取前 N 色，**力场色恒占 ≥50%** —— 「为主」的语义保留。
- 掺色顺序有讲究：先掺玩家**永远吸不了**的 S'（逼走位），L5 才把玩家的副甲色也拉进来 ——  
  那一关**吸弹与破力场开始互相排斥**，是终局该有的抉择。
- 可行性铁律只约束**必须打破的色防**（力场色 ∈ S），**不约束弹幕色** —— 骚扰色喽啰（∈ S'、逼走位）本就是同款既有设计。

### 实现上的便宜

- **新增可受击目标时零成本**：`Sword` 只认 `Damageable`，`EliteBase` 继承它，四个子类自动被光刃命中。
- 冲锋将的朝向判定**按「攻击来向」现算**（用 `player_ref` 相对本体的方向），不需要改 `Sword`。
- 指挥将的召唤物走 `Spawner.enemy` 生成 —— 是**正常喽啰**（阻塞清场、给分、可掉落），不是装饰。

## 关卡结构

```
开始界面 → 关卡选择（五关卡片，只放行已解锁）→ 择战甲（四选二）
        → 第 1 波星袭 → … → 第 N 波（中前段 / 末段由精英压轴）→ 关底旗舰
        → 结算（完成度 / 品阶 / 换甲再来 / 下一关）
```

每波的编成是「**目标色（∈ S）+ 骚扰色（∈ S'）+ 本关独有怪**」：

- **目标色**取自玩家已选的两件战甲 —— 逼你换甲；
- **骚扰色**取玩家没带的那两色，**恒定 `hover`**（停在 x≈940 远处、不追人、12 秒后自行离去）—— 逼你走位；
- 波次配色用**配额洗牌**生成，**不是独立随机**：独立随机会吐出连续 4 只同色，  
  「换甲」这个核心动词就退化成「开局选一次甲」，支柱漂移当场复发。
- 第 1 波是教学波：目标色全为同一色、无骚扰色，给一个零歧义的教学瞬间。

波次结束**不再回血** —— 生命只靠修复包补。

### 两种波次形式：推进波 / 驻留阵地波

关卡原本只有「持续向前推进」一种形式，现在插进**驻留阵地波**补**空间形式**的对比  
（推进 → 驻留 → 推进 → Boss，节奏上有个「停一下」的换气口）：

| 形式                 | 背景滚速                            | 敌人入场              | 波次副标题     |
| ------------------ | ------------------------------- | ----------------- | --------- |
| **推进波**（默认）        | `Background.SCROLL_NORMAL`（46 px/s） | 从右侧屏外飞入           | 第 N 波 · 星袭 |
| **驻留阵地波**          | `Background.SCROLL_HOLD`（**8 px/s**） | **屏内跃迁入场**        | 第 N 波 · 驻留 |

- 跃迁 x 取**屏宽 55%~95%**：够靠右（不糊在玩家脸上），又留得出反应距离。
- 位表 `StageCfg._HOLD` / 访问器 `wave_hold(s, n)`：**L1 第 2 波 · L2 第 3 波 · L3 第 2 波 · L4 第 3+5 波 · L5 第 2+4 波**。  
  每关只插 **1~2 波、压在中后段，第 1 波永不驻留**（那是教学波，整波一色到底）。
- **清场判定、波次表、数值完全复用推进波**，一行不改 —— 只改入场位置与背景滚速，  
  对既有平衡的影响接近零（不动血量 / 弹幕 / 配色 / 计分）。
- 它不是用来解决「清怪才进下一波」的 —— 那本来就有（清场判定一直存在）。它补的是**空间形式**。

### 七种独有星盗

| 关  | 机型          | 机制                                            | 分值         |
| -- | ----------- | --------------------------------------------- | ---------- |
| 通用 | 星盗          | `straight` / `sine` / `hover` / `dive` + 按色开火 | 100        |
| L1 | 拆解者 · 破片浮游机 | 死亡分裂 2 小片 + 六向抛破片                             | 150（小片 50） |
| L2 | 变节者 · 棱晶换色机 | 核心在 S 两色间每 3.5 秒轮换 + 换色破绽                     | 250        |
| L3 | 列阵者 · 方阵炮舰  | 3 艘成墙齐射，留一条规律平移的安全缝；**按组计分**                  | 300（每 3 艘） |
| L4 | 敷设者 · 引力雷舰  | 横穿全屏布设静态引力雷，8 秒自毁                             | 250        |
| L4 | 虹吸者 · 反相无人机 | 反向共振：吸收某色并回血                                  | 350        |
| L5 | 殉爆者 · 冲撞自杀舰 | 高速直冲，死 / 撞都爆半径 150 冲击环（冲撞与冲击环走**物理通道**，换甲挡不住） | 200        |
| L5 | 相位者 · 折跃刺客  | 每 2.6 秒无敌 1.1 秒 + 折跃到玩家脸上                     | 300        |

- 硬闸：分身上限 2、增援上限 6（这条就是**增殖指挥将**的召唤硬闸）、引力雷上限 8；  
  **超上限不生成、不排队**（排队会在清场时憋出一波爆发）。
- 注册表在 `scripts/entities/EnemyKind.gd`，与 `StageCfg`（纯数据）解耦，方便 `Spawner` 直接引用。

### 关底旗舰

各关旗舰的设计主题（见 `BossCfg.gd`）：

| 关  | 旗舰          | 主题与机制                                           |
| -- | ----------- | ----------------------------------------------- |
| L1 | 熔核号 · 星盗先驱  | **换甲** —— 2 阶段，全程护罩轮转                           |
| L2 | 霜噬号 · 星盗旗舰  | **走位** —— 3 阶段，全部可预判固定图形 + 呼吸窗口                 |
| L3 | 耀斑号 · 星盗炮垒  | **集火** —— 3 阶段，常驻减伤 70% + 散热期 ×3.0 / ×4.0       |
| L4 | 深渊之喉 · 星盗母舰 | **应对召唤** —— 3 阶段，子核心免伤 80% / 伤害共享 40% / 仅暴露期展护罩 |
| L5 | 终焉号 · 星盗王   | **续航** —— 4 阶段，四相重构，每相独立技能组 + 独立护罩轮转            |

- **属性护罩**（L1 / L4 / L5）：周期性展开护罩（色从玩家已选的两件战甲中抽取）。护罩开启时，  
  **只有同色光刃造成 100% 伤害，其余颜色衰减到 `_OFF_COLOR`**（L1 60% / L4 60% / L5 55%）——  
  这是逼迫玩家在战斗中换甲的核心机制。L2 / L3 不展护罩，靠各自的机制加压。
- L4 **深渊之喉**有子核心：本体免伤 80%、伤害共享 40%，只有**暴露期**才展开护罩；  
  暴露期外打子核心是白费，召唤间隔 4 秒（狂暴后 2 秒）。
- 每次换阶段：全屏清弹 + 冲击波 + 护罩重置。

### 狂暴（五关共有，机制各异）

旗舰装甲跌破本关阈值（L1~L4 **30%**、L5 **25%**）时狂暴，**一次性触发，不解除、不重复**：


- 周身泛起**血红光晕**，屏幕四周泛起血光（HUD 绘制）：缓慢呼吸 + 心跳尖峰，  
  刚进狂暴的那一下再来一次**爆闪** —— 「局面变了」这个信号一帧就能读到，不靠横幅
- 加压方式是**各关专属**的（`StageCfg` 的 `*_rage` 系列：护罩轮转间隔缩短、暴露期缩短、  
  召唤间隔缩短、散热期倍率提升……），**不再有跨 Boss 统一的四色螺旋弹幕**。  
  那条螺旋曾被误当成"狂暴标配"，但它对所有旗舰施加同一种压力，反而抹平了五关的性格差异；  
  删掉之后 L2 霜噬号的狂暴近乎纯视觉（它的主题是走位，不该在最后 30% 突然变成弹幕雨）。
- 横幅提示「狂 暴」，HUD 的血条标题转红并标注 `· 狂 暴`

> **`_selftest/` 不可删。** 它是每次改动后唯一的回归依据，删掉等于拆掉质量门禁。  
> 别卡死 PASS 条数——`_ck()` 有分支依赖随机（敌人生成、波次、掉落），同一套用例实际  
> 执行数会漂移，写死任何数字都会误判，真正的门禁是上面那三个 0。

> 自测里所有"等一会儿"的地方都**轮询状态**而不是数帧：  
> `for _i in 400: if b._st == "fight": break; await process_frame`。  
> headless 下帧率约 140fps 且抖动很大，「等 200 帧」换算不出稳定的游戏时间，  
> 数帧的写法在实机上一改帧率就假通过了。

> 后半句不是套话。GDScript 里没法从脚本侧捕获 `push_error`，而 Godot 在赋值校验失败时  
> 是**跳过赋值**而不是让坏值落下去 —— 所以像「把已释放对象赋给弹幕 target」这类缺陷，  
> 断言反而会通过，只有日志里的 `ERROR` 会暴露它。跑完务必看一眼日志。

> 坑记录：Godot 的 `Input.action_press()` 只改输入状态、不派发事件，UI 的  
> `_unhandled_input` 收不到。自测中用 `Input.parse_input_event(InputEventAction)` 走真实输入通道。

## 导出 exe

前置：本机**装过与本引擎版本完全一致的导出模板**（4.7.2.stable），  
位置 `%APPDATA%\Godot\export_templates\4.7.2.stable\windows_release_x86_64.exe`。  
模板不在项目里、也不随 Godot 附带，需单独下载（`*_export_templates.tpz`，解压后把

`templates/windows_release_x86_64.exe` 放到上述目录即可，无需整包解压）。

导出配置已写好（`export_presets.cfg`，预设名 `Windows Desktop`）：

```
Godot_console.exe --headless --path <项目目录> --export-release "Windows Desktop"
```

产物是 `build/弹幕修仙.exe` 单文件（**110 MB**，`embed_pck=true`，资源已打进 exe，可直接分发）。  
预设里排除了 `_selftest/`、`_capture/`、`tools/` —— 那是开发与取帧用的，不属于游戏。

> **导出路径的目录必须先存在**，Godot 不会自动创建，否则报  
> `准备模板: 给定的导出路径不存在`。

体积构成：**模板 exe 104 MB**（固定开销）+ 游戏资源约 6 MB。  
`fonts/simhei.ttf`（9.3 MB）是 `theme/custom_font`，也是 `DrawUtil.font()` 的加载目标，  
去掉界面会全变方块 —— 别动它。要进一步瘦身只能做字体子集化（只留界面用到的字）。

> 已清理：`fonts/` 下原本还有 `msyh.ttc`(18.8 MB) 与 `simkai.ttf`(11.2 MB)，  
> 全项目无任何引用（只有 `simhei.ttf` 被用到），却会被打进包 —— 去掉后  
> **131 MB → 110 MB**。两者都是 Windows 系统字体，需要时可从 `C:\Windows\Fonts` 取回；  
> 本项目也留了副本在 `D:\demo\_unused_fonts_backup\`。  
> 教训：**导出前先按包内清单扫一遍大文件**，字体这类"放进去就被无条件打包"的资源最容易堆积。

首次导出前装模板（只需一次，约 200 MB，不必整包解压 1.28 GB）：

```
# 1) 下载整包（1.28 GB）
https://github.com/godotengine/godot/releases/download/4.7.2-stable/Godot_v4.7.2-stable_export_templates.tpz
# 2) 只取 Windows 两个模板，放到 %APPDATA%\Godot\export_templates\4.7.2.stable\
tar -xf templates.tpz -C <临时目录> templates/windows_release_x86_64.exe templates/windows_debug_x86_64.exe
```

验证打包内容（不必真的双击 exe —— 引擎可直接加载嵌入的 pck）：

```
Godot_console.exe --headless --main-pack "build/弹幕修仙.exe" --quit-after 300
```

> 若本机启用了**应用程序控制策略**（AppLocker / WDAC），未签名的 exe 会被拒绝启动  
> （`应用程序控制策略已阻止此文件`），这与导出是否成功无关 —— 换台机器或让管理员放行即可。  
> 个人电脑上更常见的是 SmartScreen 首次警告，点「更多信息 → 仍要运行」即可。
